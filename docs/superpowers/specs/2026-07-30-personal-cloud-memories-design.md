# 双人个人云端回忆设计

## 目标

将当天照片和当天记录从“同一浏览器的本地内容”改为“双人空间内各自拥有的云端内容”。每位成员可以在任意已登录设备查看双方内容，只能添加、修改和删除自己创建的内容。已存在于旧浏览器本地的照片不迁移。

## 用户界面

- 在当天照片和当天记录之前放置一个紧凑的分段切换控件：`我的` 与 `对方`。它采用细边框、低视觉权重的文字按钮，而非现有保存、添加照片等主操作样式。
- 默认显示 `我的`。该视图显示添加照片、记录输入框、保存记录和删除入口。
- 切换到 `对方` 时，显示对方当天照片和记录；图片可点开大图，记录以排版后的只读内容显示，不出现上传、保存、删除或可编辑输入框。
- 照片缩略图不显示名称；每张图右上角有圆形 `×` 删除控件。它只在“我的”视图中出现，点击后要求确认“确定删除这张照片吗？”。
- 双方都没有内容时，分别显示明确的空状态。切换不会修改任何云端数据。

## 数据与权限

### 每人每天一篇记录

- `daily_notes` 的唯一约束从 `(couple_id, date)` 变为 `(couple_id, date, created_by)`。
- 新版 `save_daily_note` 只以上传者为当前登录用户创建或更新；新版 `delete_daily_note` 只删除当前登录用户的同日记录。
- 两名活动配对成员可以读取同一 `couple_id` 下的记录；写入、更新和删除必须由记录创建者执行。
- 历史共享记录保留，但未指定迁移归属的旧记录继续归属于既有 `created_by`，不复制给另一位成员。

### 私有云端相册

- 新增 `daily_photos` 元数据表和名为 `date-photos` 的 private Supabase Storage bucket。
- 每个对象路径为 `<couple_id>/<date>/<photo-id>.<extension>`；元数据记录所属空间、日期、上传者、文件类型、尺寸、排序与创建时间。
- 每个成员每天最多上传 30 张自己的照片。照片读取对当前双人空间成员开放，插入与删除限制为上传者本人。
- 页面通过短时签名 URL 显示私有照片。浏览器端只使用 publishable key；不把 service role、数据库密码或令牌写入客户端、Git 或 Vercel。
- 上传先写入私有对象，再安全创建元数据；若元数据失败，清理本次上传对象。删除使用受控服务，同时移除元数据和对象，失败时保留界面中的原照片并显示错误。
- 不读取、上传或删除旧 IndexedDB 中的照片。新版本上线后仅使用云端相册。

## 客户端边界

- `BookingSnapshot` 包含带创建者身份的 `dailyNotes` 和 `dailyPhotos`。
- 云端预约仓库在一次并行加载中获取记录、照片元数据和现有日历数据，并订阅两张新表的实时变更。
- 照片仓库负责签名 URL、上传、删除和按日期/创建者读取；页面组件不直接调用 Supabase。
- 切换控件仅切换当前显示的创建者身份。页面根据当前身份决定编辑态与只读态，不能依赖 CSS 隐藏作为权限控制。

## 错误与同步

- 断网时可以查看已加载内容，但上传、保存和删除显示明确的网络提示；不支持离线排队写入。
- 上传、保存或删除成功后重载快照；实时订阅使对方已打开页面自动获得更新。
- 上传不支持的文件、超过本人每日 30 张、无配对、存储失败和权限失败各显示稳定中文提示。

## 验证

- 组件测试覆盖默认“我的”编辑态、切换“对方”只读态、图片名称隐藏、圆形删除按钮、取消确认和确认删除。
- 仓库测试覆盖创建者筛选、签名 URL、私有上传、删除失败不移除界面项和按本人计数。
- 数据库测试覆盖双人可读、本人写删、对方不能修改或删除、第三方与匿名无法读取，以及 30 张个人每日上限。
- 生产验收使用两台设备和两个已配对账号：双方分别上传、分别写记录、换设备查看、切换查看对方、验证只读和删除权限。

## 不做

- 不迁移当前浏览器 IndexedDB 中的旧照片。
- 不支持第三人、公共分享、离线写入、照片标题编辑或多人相册。
