# 我们的约会日历

这是一个为两个人设计的本地版约会预约网页。双方都可以标记空闲时间、发起约会邀请，并由接收方确认、拒绝或提出调整。

当前版本先在一台电脑的浏览器中保存数据，适合学习、体验和修改。后续接入云数据库后，才能让两台手机在不同网络中同步使用。

## 你需要知道的四个概念

1. **React** 负责把页面拆成日历、表单、提醒等小组件。
2. **TypeScript** 为预约、身份和状态定义固定格式，减少写错数据的可能。
3. **localStorage** 是浏览器自带的本地存储；刷新页面后数据仍在，但换浏览器或清除网站数据后不会保留。
4. **自动测试** 会模拟规则和真实浏览器操作，帮助我们确认修改没有破坏已有功能。

## 第一次启动

在 PowerShell 中进入项目目录，然后依次运行：

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

终端会显示一个本地网址，通常是：

```text
http://127.0.0.1:5173
```

把它复制到浏览器打开即可。默认专属口令是：

```text
our-date
```

## 修改专属口令

打开 `.env.local`，修改等号右边的内容：

```dotenv
VITE_SHARED_PASSPHRASE=你们自己的口令
```

修改后重新启动 `npm run dev`。不要把 `.env.local` 上传到公开仓库，它已经被 `.gitignore` 忽略。

本地口令只能避免别人随手打开页面，并不是真正安全的登录。上线阶段需要使用云端身份验证。

## 怎样使用

1. 输入专属口令。
2. 选择“我是他”或“我是她”。
3. 在日历点击某一天，保存自己的空闲时段。
4. 进入“发起约会”，选择日期、时段、活动和备注。
5. 切换为另一方身份，在铃铛提醒或“我的安排”中打开邀请。
6. 接收方确认、拒绝或提出调整。
7. 如果接收方提出调整，原发起方决定是否接受。

## 项目结构

```text
src/
├─ app/             应用入口、路由、身份会话和数据仓库接口
├─ domain/          预约规则、状态变化、空闲时间和数据类型
├─ features/
│  ├─ calendar/     共享月历与空闲时段
│  ├─ invitations/  发起、列表、详情、确认和调整
│  ├─ notifications/网页内提醒
│  └─ session/      口令入口与身份选择
├─ storage/         localStorage 本地数据实现
├─ styles/          颜色、布局和响应式样式
└─ test/            测试数据构造工具

e2e/                真实 Chromium 完整流程测试
```

最重要的设计原则是：页面不直接读写 `localStorage`，而是通过 `DateBookingRepository` 数据仓库接口。以后换成云数据库时，主要替换存储层，不需要重写日历和预约页面。

## 自动验证

运行所有单元测试和组件测试：

```powershell
npm test
```

检查 TypeScript 并生成生产版本：

```powershell
npm run build
```

运行真实浏览器完整流程：

```powershell
npm run e2e
```

端到端测试会验证双方发起与确认邀请、未读提醒、本地持久化和手机宽度无横向溢出。

## 数据放在哪里

当前数据保存在浏览器的 `localStorage` 中，键名是：

```text
couple-date-booking
```

如果数据损坏，网页会显示“本地数据无法读取”，并提供二次确认后的重置按钮。重置只删除本应用的数据，不会清除其他网站的数据。

## 当前版本尚未包含

- 两台设备之间的数据同步
- 真实邮件提醒
- 安全的双人账号登录
- 固定公网网址和域名
- 照片墙、纪念日和约会统计

这些属于下一阶段的云端版本。当前代码已经把存储接口独立出来，为后续升级保留了清晰入口。
