# 留一页给我们

这是一个为两个人设计的约会预约网页。双方可以使用各自的邮箱账号登录，并通过一次性邀请码建立两人空间。

当前已接入 Supabase 账号、双人配对、共享日历、预约、通知和每日记录的云端同步。旧浏览器本地数据不会自动上传到云端。

## 你需要知道的四个概念

1. **React** 负责把页面拆成日历、表单、提醒等小组件。
2. **TypeScript** 为预约、身份和状态定义固定格式，减少写错数据的可能。
3. **Supabase Auth** 为两人提供独立邮箱账号、邮件验证与“保持登录”。
4. **自动测试** 会模拟规则和真实浏览器操作，帮助我们确认修改没有破坏已有功能。

日历支持月、年、连续 5 年三种尺度。邀请的全天、上午、下午、晚上是互相独立的多选项，选中哪些就占用哪些时段，不要求连续。

## 第一次启动

在 PowerShell 中进入项目目录，然后依次运行：

```powershell
npm install
npm run dev
```

首次运行前，按 [Supabase 配置说明](docs/supabase-setup.md) 创建 `.env.local`。该文件只保存项目 URL 和 publishable key，已经被 Git 忽略。

终端会显示一个本地网址，通常是：

```text
http://127.0.0.1:5173
```

把它复制到浏览器打开即可。两人分别注册并验证邮箱：第一人创建空间，第二人使用 7 天有效、只能使用一次的邀请码加入。勾选“保持登录”后，关闭并重新打开浏览器仍会恢复账号状态。

## 怎样使用

1. 使用各自的邮箱注册并完成邮件验证。
2. 第一人选择自己的身份并创建两人空间。
3. 将页面显示的邀请码发送给另一人。
4. 第二人登录后输入邀请码，系统会自动分配相反身份。
5. 配对完成后，双方会进入共享日历；空闲时间、预约、确认、通知和每日记录会同步到两人空间。

日历颜色图例：珊瑚色整格表示已确认行程；青绿色点表示他有空；粉紫色点表示她有空；金色点表示当前用户需要处理邀请；浅金色点表示等待对方处理。照片和文字记录会分别显示记忆标记。

## 项目结构

```text
src/
├─ app/             应用入口、云端身份会话和配对状态
├─ domain/          预约规则、状态变化、空闲时间和数据类型
├─ auth/            Supabase Auth 与配对网关
├─ features/
│  ├─ calendar/     月、年、5年日历与空闲时段
│  ├─ invitations/  发起、列表、详情、确认和调整
│  ├─ notifications/网页内提醒
│  └─ session/      注册、登录、邮箱验证和双人配对
├─ storage/         localStorage 数据与 IndexedDB 照片实现
├─ styles/          颜色、布局和响应式样式
└─ test/            测试数据构造工具

e2e/                真实 Chromium 完整流程测试
```

配对、邀请码和成员身份由云端数据库函数控制。邀请码只在创建时显示一次，数据库仅保存其摘要，不能被直接读取。

## 自动验证

运行所有单元测试和组件测试：

```powershell
npm test
```

检查 TypeScript 并生成生产版本：

```powershell
npm run build
```

运行真实浏览器完整流程：

```powershell
npm run e2e
```

端到端测试会验证预约流程；单元、组件和数据库测试覆盖账号会话、邀请码、双人上限和访问权限。

## 部署到公网

本项目通过 Vercel 发布静态网页，Supabase 负责账号认证和数据库访问控制。部署时仅配置公开的 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`，详细规则见 [Supabase 配置说明](docs/supabase-setup.md)。

## 当前版本尚未包含

- 真实邮件提醒
- 云端照片同步（云端目标上限为每日期 30 张）
- 照片分页、批量上传和自动分类

这些属于下一阶段的云端版本。当前代码已经把存储接口独立出来，为后续升级保留了清晰入口。
